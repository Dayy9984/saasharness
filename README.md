# SaaS Harness

A lean B2C SaaS starter assembler for **React Web + Cloudflare**.

The harness does not try to generate every architecture from scratch. It turns three human-approved contracts into a deterministic starter plan, activates versioned module boundaries, generates a web-only Cloudflare workspace, and routes verification by change risk.

## Status

`v0.1` is an executable foundation, not a production-ready auth or payment platform.

- Contract validation, product resolver, module selection, starter assembly, and risk routing are implemented.
- Kakao, Google, and market payment adapters are contract boundaries only.
- A monetized project remains `productionReady: false` until a real payment adapter is selected and validated.
- Mobile output is intentionally unsupported in v0.1.

## Why this shape

```text
Product interview
→ React UX approval
→ Starter assemble
→ Feature WIP=1
→ risk-adaptive TDD / scenario-first implementation
→ focused verification
→ limited critic
→ Preview → Staging → Production
```

Quality should primarily come from the reusable starter and module boundaries, not from a large number of agents or gates.

## Requirements

- Node.js 22+

The harness core has no runtime dependencies.

## Quick start

```bash
npm install
node ./bin/saasharness.js init ./example-contracts --name my-saas
# Edit product.yml, ux.yml, and feature.yml. Set each approval.status to approved.
node ./bin/saasharness.js validate ./example-contracts
node ./bin/saasharness.js plan ./example-contracts
node ./bin/saasharness.js assemble ./example-contracts --out ./generated/my-saas
node ./bin/saasharness.js risk src/modules/billing/public.ts
```

Install the generated project's dependencies separately:

```bash
cd generated/my-saas
npm install
npm run check
npm test
```

## Canonical inputs

- `product.yml`: product, market, monetization, capabilities, platform constraints, approval
- `ux.yml`: approved primary journey, states, motion, usability evidence, approval
- `feature.yml`: the single current feature slice, affected surfaces, acceptance, approval
- `module-lock.json`: generated by the assembler

## Commands

| Command | Purpose |
|---|---|
| `init` | Create draft contracts |
| `validate` | Block unapproved or incomplete contracts |
| `plan` | Resolve region defaults, modules, Cloudflare services, DB profile, and warnings |
| `assemble` | Generate the React + Cloudflare starter |
| `risk` | Select the smallest relevant verification set for changed paths |

## Safety model

- Web-only output by default.
- Product features import module `public.ts` boundaries only.
- Provider SDKs and protected persistence stay behind adapters.
- Unresolved payment integration is a production blocker.
- Product-owner approval is not treated as target-user usability validation.
- Self-improvement, exhaustive UI sweeps, and broad hidden-eval systems are outside the core runtime.

## Validation

```bash
npm run check
```

The repository uses Node's built-in test runner so the harness itself can be validated without downloading test frameworks.
